# HRMS critical-journey E2E test report

Date: 1 November 2026 (IST)

**Result:** 132 API E2E checks passed from fresh synthetic organizations; 332 backend regression tests passed with zero failures, errors or skipped tests. Frontend production build passed. Browser smoke tests passed for the flows listed below.

This is verification of the critical organization, access and subscription journeys below, not a claim that every HRMS module or external integration has completed production certification.

## Isolation

Testing used a dedicated `hrms_e2e_20261101` PostgreSQL database, backend port 8082 and frontend port 5174. Only schema definitions and role/permission reference data were copied; no real organization or employee rows were copied. All test accounts and employee records were synthetic. Expiry manipulation was confined to this disposable database. The normal backend/database on port 8081 was not used for test mutations.

## Verified API journeys

- Missing initial administrator credentials are rejected; complete organization creation provisions a ready workspace and usable administrator login.
- Software and medical organizations receive different department/position catalogs. New organizations start with Legacy access and no fabricated subscription dates.
- Unauthenticated access, cross-organization company selection and cross-organization billing access are rejected.
- Deleting the current login organization is rejected by the API.
- An organization administrator can activate Free; only a platform administrator can use the temporary payment bypass.
- Free enforces 20 active employees and one branch; Basic enforces 50 active employees and two branches.
- Employee creation, single restoration and bulk restoration enforce capacity. A batch that exceeds capacity rolls back in full.
- Two concurrent employee creations racing for the last Basic slot yield exactly one success and one capacity rejection.
- Branch archive releases branch capacity; restoration is denied when it would exceed Free and allowed after upgrading to Basic. An over-limit downgrade is rejected.
- Employee login, required initial password change and own profile access work. Employee directory/billing administration are denied.
- CEO gets organization workforce, payroll and billing access, while platform administration is denied. COO gets workforce access while billing, payroll and privilege configuration are denied.
- Revoking a CEO position policy takes effect immediately for an existing session token.
- Creating an employee directly with a branch-admin role succeeds. That administrator can access its own workforce but cannot read or bulk-edit head-office employee IDs.
- Monthly manual renewal preserves the original start date and extends expiry. Reusing the same request does not extend twice. Separate exploratory checks confirmed mismatched request reuse is rejected.
- Unconfigured Stripe Checkout returns a clean 503 response.

Additional isolated exploratory checks passed for paid-plan expiry (workforce 402, login/renewal still available), annual activation restoring access, avatar upload persistence, and fetching the uploaded file intact.

## Browser verification

- Synthetic platform administrator logs in and sees both test organizations.
- Company selector opens over page content and selects the requested organization.
- Subscription page follows the selected organization and displays all four fixed-price packages.
- Free selection opens a confirmation; activation updates the current plan to Free Active and usage limits to 20 employees / one branch.
- Employee list renders the selected head office and the uploaded synthetic avatar.
- Selecting a medical organization in New Employee loads its departments. Selecting Clinical Services limits job positions to its medical positions.

## Defects fixed during testing

1. **Bulk activation bypassed employee limits.** Routed bulk activation through the same transactional restoration/capacity guard as single restoration. Routed bulk archiving through the guarded service as well. Verified batch rollback and concurrent creation.
2. **Branch administrator could access an out-of-scope employee by ID.** Added a shared employee lookup guard for company, department and self scope; applied it to detail/mutation paths and bulk/import work-information updates. Work-information references must belong to the employee company.
3. **Direct branch-admin onboarding failed.** Establish the employee's baseline self-service membership before validating the requested scoped administrator role. Canonical role authorization remains in place.

Regression coverage was added in backend `EmployeePlanLimitTest` and `EmployeeScopeGuardTest`.

## Repeating the API run

Use `scripts/e2e-critical-flows.py` with a **disposable** backend at `http://127.0.0.1:8082`. The runner deliberately has no URL override for the normal backend. It requires an existing synthetic platform administrator, ready database schema/reference permissions, manual billing enabled and Stripe keys absent. It creates new test organizations on every run. Tokens and generated passwords stay in memory and are excluded from the JSON report.

Provide `HRMS_E2E_USERNAME` and `HRMS_E2E_PASSWORD` in the test environment, then run:

```sh
python3 scripts/e2e-critical-flows.py \
  --confirm-disposable-database \
  --report /private/tmp/hrms-e2e-results.json
```

The runner does not drop databases or delete fixtures. Stop the dedicated services and discard the disposable database after testing. Do not run it against a backend connected to real organization data.

Build/test commands used:

```sh
# Backend: Java 24, prod profile, disposable DB credentials and JWT secret supplied in environment
mvn -q -Dfrontend.skip=true test

# Frontend
npm run build -- --outDir /private/tmp/hrms-ui-check-build
```
