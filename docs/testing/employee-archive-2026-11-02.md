# Employee archive / restore — 2 November 2026

Replaced employee directory Deactivate / Activate labels with Archive / Restore. Added Archived employees tab using archived=true for both scoped and global listings. Requests preserve archive state across company filters, pagination, imports and reloads. List requests ignore stale responses so switching tabs does not mix active and archived records. Separate employment and login-hold labels are retained.

Archive preserves the employee and linked HR records and excludes them from active capacity counts. Authentication now derives archival status from inactive employee rows in the account's assigned tenant schemas, on each authentication/JWT read. Archived employment blocks both password sign-in and subsequent requests using existing bearer tokens. Restoring respects current subscription capacity and leaves user activity, login holds and role grants unchanged. An account with another archived linked employee record remains blocked; archiving applies to the linked login account across companies.

Archive/restore endpoints and update/status compatibility paths reject self changes and platform-administrator targets. Company access is checked before mutations. Company-scoped administrators must have access to every effective role assignment of the linked account. Permanent deletion remains a separate platform-admin operation. No new schema migration is needed.

Validation: frontend production build; 32 focused unit tests (EmployeeArchiveGuardTest 6, EmployeeArchiveTest 6, EmployeeLoginHoldTest 13, AuthPasswordResetTest 7); 2 EmployeeArchiveIntegrationTest checks against disposable PostgreSQL database with the existing V27 job-position migration applied. Verified actual SQL-based authentication blocking after archival, successful restoration, preserved holds and disabled-account state. Test transactions rolled back and the disposable database was dropped. No real employee account was archived or restored during verification.
