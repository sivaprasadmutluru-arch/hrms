# Staffing, contract assignments and client billing — 3 November 2026

## Entry point and access

Open Accounting → Staffing & contracts (`/accounting/staffing`). The Accounting page also links to it. The module uses the selected company, existing finance role checks and company-wide payroll access. Self/department scopes and payroll-excluded positions cannot access it. Reads require payroll:view; all writes and approval actions additionally require payroll:approve. This first version is managed by authorized administrators/finance users, including recording time on behalf of workers; it does not add an employee self-service staffing view.

## Workflow

1. Create the worker using the existing Employees flow. Configure the worker classification separately: employee, independent contractor or vendor worker; permanent/fixed-term; hourly/salaried; vendor company if applicable. Existing workers remain unconfigured until explicitly reviewed.
2. Record work authorization separately, including category (H-1B, EAD, OPT and others), sponsoring employer where relevant, validity dates, case/internal reference and an optional link to an existing document belonging to the same employee/company. Documents are managed through the existing employee Documents workflow. Dates show expiry reminders for HR review. No immigration decision or login restriction is automated.
3. Create a client, then an assignment with project/client contract reference, work location/state/country, dates, pay/bill rates, explicit overtime rates and an optional existing payroll contract link. Rates use the company's configured currency. Currency is not inferred from country or visa.
4. Enter daily regular/overtime hours or import an existing Project timesheet once. Imported worker/date/total hours must match the source. Changed sources require review before approval or billing. Daily totals across assignments cannot exceed 24 hours.
5. Submit, approve, or return time for correction with a reason. Optimistic versions prevent stale edits. Approved hours retain rate snapshots; changing an assignment does not rewrite them. Linked invoice hours cannot be changed until the invoice is voided.
6. Export approved time as an Excel payroll-preparation basis. The export includes worker classification, linked payroll contract and hourly pay reference formulas. Salaried/vendor workers do not receive an invented hourly salary total. Use existing Manual Payroll for actual payslips; this module does not create or mark salaries paid.
7. Select approved, unbilled hours for one client to create a draft invoice. Tax percentage is entered/reviewed by finance, never inferred. Issuing creates a balanced receivable/revenue/tax-liability journal. Invoice lines and client billing information are snapshotted.
8. Record an actual bank/cash client receipt with date/reference. Partial receipts are supported; overpayment and duplicate requests are rejected or returned idempotently. Client receipts do not alter employee payslip status or transfer funds.
9. Void a draft or unpaid issued invoice with a reason. Issued journals are reversed and the original invoice/lines remain in history; time is released for correction/rebilling. Invoices with recorded receipts require finance reconciliation and cannot be voided here. Reversing linked journals directly in Accounting is visible as a reconciliation warning.

Client invoice Excel files contain billing rates and service amounts, never employee pay rates or visa records. Payroll-basis exports remain finance-restricted. Audit records retain modifications and actors. No emails or external submissions are sent by this module.

## Validation

20 new PostgreSQL/Spring integration tests passed, alongside 31 accounting integration tests and 7 payroll parser tests (58 total). Coverage includes the complete invoice/partial receipt flow, balances and tax liabilities, idempotent issue/receipt, overpayment and void restrictions, rebilling after reversal, stale edits, daily hour limits, approval transitions, rate snapshots, source Project timesheet changes, scoped authorization documents, visa/classification independence, company/employee/read-only access exclusions, currency changes and Excel formulas/content segregation.

The production frontend build passed. Browser checks verified the six tabs and worker, authorization, client, assignment and timesheet forms on the local app. Tests ran against a disposable database; no live worker classification, authorization, hours, client invoice or receipt records were created. Migration V45 was applied to the local database and the backend restarted.

## Boundaries

This is a staffing operations and bookkeeping workflow. It does not determine employee/contractor status, immigration eligibility, prevailing wage, overtime entitlement or tax liability. It does not submit immigration forms, W-2/1099 filings, client payments, refunds, or payroll automatically. Supporting files use existing employee Documents rather than a new public file store. Automated email expiry reminders, employee self-service staffing entry, legal contract generation/e-signing and statutory invoice/tax filing integrations are not included.
